# Паутина зала — локальный прототип

Для запуска нужен Node.js 20+. В папке проекта выполните `npm install`, затем `node server.js`. Откройте http://localhost:3000. Пульт: /admin, пароль для локального теста `demo` (можно задать переменной ADMIN_PASSWORD). Экран: /screen. Тестирование 20 игроков на одном телефоне: /play?test=1. Выбирайте номер, регистрируйте участника и переключайтесь между номерами; результаты сохраняются в браузере и на сервере. Телефон и компьютер должны быть в одной сети; вместо localhost используйте IP компьютера и разрешите входящие подключения к порту 3000.

Это прототип: отсутствуют Socket.IO, обязательный расширенный граф, полноценное взаимное паросочетание, фильтр нецензурных ников, защита и ограничение запросов, HTTPS, Docker, экспорт и нагрузочный тест. Его нельзя считать готовым для публичного мероприятия. При перезапуске сервер восстанавливает последний снимок, записанный раз в 10 секунд. Не используйте этот пароль и прототип в интернете.

На экране зала QR для входа появляется только после установки `PUBLIC_URL` в файле `.env`: укажите реальный публичный HTTPS-домен, например `PUBLIC_URL=https://game.example.com`. Локальные IP-адреса и HTTP намеренно не выводятся в QR. Сам по себе PUBLIC_URL не настраивает HTTPS и доступ извне.

Команды настраиваются в `content/teams.json`: заполните `maxUrl` реальными HTTPS-ссылками MAX. Пустую ссылку интерфейс обозначает как ненастроенную. Кнопка игрока проходит через `/go/:teamId`; число переходов хранится в состоянии игры. Признак `adult` обозначает сегмент, но не проверяет возраст и не ограничивает доступ.

Демонстрация без изменения реальных участников: `/screen?demo=100&phase=LOBBY` (число 100–300). Для проверки графа знаний используйте `phase=ROUND_ACTIVE`, для команд — `phase=TEAMS_FORM`. Повтор анимации запускается в `/admin`. Роли ранее добавленных участников не угадываются: в фазе команд они могут выбрать их на телефоне.

Клиентская визуализация использует canvas и ForceAtlas2 для позиций планет, вычисленных на сервере. Проверка производительности на 200–300 телефонах и читаемости с 30 метров ещё не проводилась.

Графика берётся из `ready/` в корне проекта; подготовленные WebP находятся в `public/assets/`. Команда `node scripts/build-assets.cjs` пересобирает изображения из исходников через sharp. Шрифты WOFF2 и файлы лицензий OFL находятся в `public/assets/fonts/`. Рендер /screen проверен в локальном Chromium на 1024×768, 1280×720, 1920×1080, 2713×1218 и 3840×2160. Читаемость с расстояния и сканирование QR в зале требуют проверки на реальном экране.

## Адаптивный экран зала

`public/screen.css` задаёт макет непосредственно по размеру окна, без фиксированного холста 1920×1080 и CSS transform. Общая анимация `main` для экрана отключена. На проверенных горизонтальных разрешениях граф занимает 64–68% площади окна.

В `public/screen.js` серверная ForceAtlas2-раскладка уточняется с учётом размеров орбит и подписей. Геометрия кешируется до изменения данных или размера canvas. Участники распределяются по орбитам; их ники показываются по одному в верхней строке, а три сильнейшие связи — в нижней полосе. Уже подключённые игроки видны сразу; новые появляются с анимацией, повтор запускается из пульта. Граф знаний тоже размещает подписи без пересечений.

Проверки: `npm test`, `node scripts/check-screen.cjs`, `node scripts/check-phone.cjs`. Для проверки настоящего браузерного рендера запустите сервер и `node scripts/check-screen-browser.cjs`. Нужен уже установленный Playwright/Chromium; путь к существующему модулю можно указать в `PLAYWRIGHT_MODULE`. Скрипт проверяет границы, пересечения подписей, долю графа, фазы и появление нового игрока; сохраняет снимки в `artifacts/screen/`. Он не меняет состояние игры на сервере. Это проверка визуализации 100–300 игроков, а не нагрузочный тест 300 телефонов.
